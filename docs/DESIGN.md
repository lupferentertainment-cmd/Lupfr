# Design

**Navigation active-section boundary.** The home scroll-spy samples one CSS pixel below `SECTION_SPY_OFFSET_PX`. Hash scrolling can place a section at a fractional coordinate just above the nominal 120px line because document positions are fractional while `scrollY` is rounded; the one-pixel inset ensures the newly targeted section, rather than the immediately preceding section, owns the gold underline and `aria-current`. The underline exposes `data-lupfr-nav-underline` solely for the real-browser regression gate, which requires exactly the clicked link to own both `aria-current` and the full-width visible underline. Ordinary scroll tracking and the configured header padding remain unchanged.

**Product.** Marketing site for LUPFR Entertainment: hero, corporate-partners strip (slim marquee directly under the hero with a small centered “Corporate Partners” eyebrow), events list + event detail pages (each with its own photo gallery), services, artists, about, our team (a founders row above a roster grid with LA / SF filter boxes), contact form, newsletter signup, footer (now also home to the email / location / phone contact info). Single primary scroll on home; event detail is a dedicated route. The same contact form also lives at **`/contact`**; hero and nav “Book an Event” link there (`CONTACT_PAGE_PATH` in `lib/site.ts`), while the home section remains scroll-targetable as `#contact`. The blog source remains in the repo but is temporarily disabled for public access: **`/blog`**, **`/blog/[slug]`**, and the blog hosts return 404 while `BLOG_PUBLIC_ACCESS_ENABLED` is `false`, and Blog is hidden from navigation, footer links, sitemap, and route crawls. Blog articles are preserved as long-form LUPFR operator essays: every article must name a specific LUPFR event or situation, speak from a first-person operator/founder angle, and state an opinionated thesis instead of generic event-marketing advice. YAML body lines may use markdown-style markers (`##`, `###`, `>`, `-`, and `**Source note:**`) that render as animated headings, subheads, pull quotes, bullets, and source-note cards with lighter, thinner prose typography sized for denser long reads. Unknown URLs use a self-contained `app/not-found.tsx` document (plain logo image and home link) so 404 responses do not depend on the normal client navigation bundle.

**Metallic gold (theme).** In `app/globals.css`, **light** (`:root`) uses a restrained low-glare neutral stage (`#f0f0ed`) with soft-white card/popover surfaces (`#fafaf8`), near-black `#151515` ink, visible neutral borders, and bronzed luxe gold accents. This supersedes the earlier pure-white/faded light treatment: cards and photography must remain distinct instead of dissolving into the page. Light headings use `--gradient-heading-gold`, a bronzed gold gradient so metal reads as luxurious bronze on a calm surface rather than glare. **Dark is still the default** (`ThemeProvider defaultTheme="dark"`, system theme disabled) and `.dark` retains the locked white-gold palette, so light-mode tuning must not change it. Hero **LUPFR** and rotating taglines use brighter `--gradient-hero-gold` plus `.hero-tagline-contrast`, a stable edge/shadow that survives bright and dark video frames without changing the mono/uppercase style; `.hero-scroll-cue` similarly uses high-contrast white with a video-safe shadow and gold hover/focus. Hero outline CTAs use `.hero-outline-cta` so their white text/border stay legible as video luminance changes in either theme. The **Entertainment** line remains plain uppercase `text-foreground`. Hero metallic motion and the `GoldShineText` heading pipeline remain unchanged.

**Metallic gold — preserve (no accidental regressions).** This is the **intended brand look**: do not swap dark mode to a different metal (e.g. **copper / bronze** low-hue sets) or drop hero shimmer without an explicit product decision. **`tests/unit/globals-gold-theme.test.ts`** asserts the canonical light `--gradient-heading-gold`, locked dark `--gold*` / `--btn-gold*` / `--gradient-heading-gold`, entertainment lines, and the presence of **`hero-shine-pass`** + **`hero-gold-shine-*`**. If you change the palette on purpose, update **`app/globals.css`**, that test, and this sentence in the same change set.

**Mobile performance (≤767px).** Goal: home usable in **~2–5s** on phone/low-compute (budgets in `tests/performance/mobile-budgets.json`). Hero uses a static grid/orbs (no continuous Motion loops), **lighter Gaussian blurs** on the static orbs than on desktop-lite/reduced-motion, longer hero phrase rotation, **HD `next/image` mobile poster first** (retina ~1600×2133 yacht still at `/hero/hero-poster-yacht-mobile.webp` via `HERO_POSTER_{DARK,LIGHT}_MOBILE`) so phone LCP stays sharp, then the **same full-quality yacht MP4** (`HERO_VIDEO_*`) may fade in after `window` load + idle — skipped when `prefers-reduced-motion` is set (mobile perf gate uses reduced-motion, so it stays poster-only); desktop still mounts video immediately, **static** metallic taglines via `GoldShineText` `variant="static"` and a static Entertainment line (no hero-level `useScroll` / parallax subtree), and a non-animated scroll hint. Below-fold home sections (`#services`–`#contact`, not `#events`/hero) use mobile-only `content-visibility: auto` with a generous intrinsic size so off-screen layout is skipped without breaking hash scroll; photo-card shimmer (`SkeletonShimmerLayer`) delays ~200ms so fast loads never flash. Both mobile poster and desktop video media share `.lupfr-hero-media-wash`, a restrained top/mid overlay with only the bottom strengthened for page transition, so the hero photo/video remains visible behind the brand lockup. `components/hero.tsx` uses **`next/dynamic`** to load **`components/hero-desktop.tsx`** only when `useIsMobile() === false` so **phone/tablet-first viewports skip downloading desktop-only chunks** (dual MP4s, orb animation loops, `useScroll`/parallax, scroll-linked `GoldShineText`). Featured Artists uses a static mobile grid capped at six plain `next/image` cards, with direct social links, no carousel controls, and no embedded music iframes; the lightweight all-name roster remains visible below. Prefers-reduced-motion for the hero uses **`hooks/use-prefers-reduced-motion.ts`** (`useSyncExternalStore`) rather than tying the shell to Framer Motion. First-load JS on phones is further reduced by the layout **`MotionProvider`** (`LazyMotion` / `domAnimation`, non-strict) so initial-chunk sections pay for the lighter motion feature set. **Desktop / laptop (≥768px)** is **not** globally downgraded: when `useIsMobile() === false`, the hero still loads the desktop chunk (`preload="auto"` videos, scroll parallax, scroll-linked fade, scroll-driven title + rotating phrase shine). Top scroll progress bar is omitted (and its Framer `useScroll` subtree does not mount, avoiding extra scroll-linked work). Breakpoint matches `hooks/use-mobile.ts` (`useLayoutEffect` for earlier, pre-paint width read).

**Scroll-driven motion (flicker avoidance).** Until `useIsMobile()` resolves (`undefined`), the site treats the viewport as **not desktop-confirmed**: hero matches the **mobile** subtree (HD poster + deferred video, no hero `useScroll`) and the top scroll progress bar stays hidden. After mount, only `isMobile === false` (≥768px) mounts the **desktop** hero subtree (dual videos, parallax, scroll-linked fade + `GoldShineText` scroll variant on rotating lines), plus scroll progress. `ScrollReveal` uses one `m.div` with scroll-linked opacity/transform from the first client paint (no interim plain `div` at full opacity). Section titles and below-the-fold `GoldShineText` still use `useScroll` with `layoutEffect: false` when the measured target is a parent ref, avoiding Framer “ref not yet hydrated” warnings under Strict Mode. Desktop rotating hero taglines use `GoldShineText` with the hero `section` ref (metallic gold, not flat accent); mobile uses `variant="static"`. Phrase changes use a short vertical + blur crossfade unless `prefers-reduced-motion` (opacity only). Section **lead paragraphs** (Services, Brands, Contact, Featured Artists) and the service/brand **detail-page descriptions** use **`components/text-reveal.tsx`** (`TextReveal`) — the About story stays static because its paragraphs embed rich `GoldShineText`/`BrandSlashText` markup that the string-only `TextReveal` cannot carry. `TextReveal`: a per-word staggered rise + fade (`whileInView`, `once: true`, opacity + transform only — no filter blur) with `aria-label` on the container and `aria-hidden` word spans so screen readers get one sentence; `prefers-reduced-motion` renders the static text.

**Framer / dev console.** Motion-animated colors and shadows use `rgba`/`#hex` (not `oklch()` in `animate`/`whileHover`) so Framer can interpolate. Hero video hints use `<video preload>` only (no `react-dom` `preload` with `as: "video"`—React warns). The first event card uses `next/image` `priority`/`fetchPriority` instead of root `<link rel="preload">` for the raw file path (optimizer URL would not match).

**Scroll smoothness vs flicker.** `html { scroll-behavior: auto }` keeps wheel/trackpad scrolling in sync with Framer `useScroll` (native `smooth` fights scroll-linked opacity/transform). `ScrollReveal` renders scroll-driven motion immediately—no pre-mount plain `div` at full opacity (that caused a flash when switching to opacity 0 below the fold). Body omits long `background-color`/`color` transitions so theme and scroll motion don’t compound into visible shimmer.

**Gold controls and cards (owner rollback 2026-07-08).** Key CTAs (nav **Book an Event** + **Schedule a call**, Artists **Submit Your Mix**), **Team filter chips**, **Team cards**, and **Featured-artist cards** use the existing CSS gold button/pill styling plus `GoldCard` / `ArtistCard` behavior. Do not add animated shader/canvas wrappers or extra visual-effect package dependencies around these controls without an explicit product decision and matching performance tests; the preferred state is the pre-ring gold button design with desktop card tilt intact and mobile tilt disabled via `useIsMobile()`.
