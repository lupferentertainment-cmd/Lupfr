# Design

**Product.** Marketing site for LUPFR Entertainment: hero, corporate-partners strip (slim marquee directly under the hero — logo row only, no visible section text; eyebrow removed by owner request 2026-07-11), events list + event detail pages (each with its own photo gallery), an Instagram **Reels** block inside Events, services, artists, about, our team (with LA / SF / Exec filter boxes), contact form, newsletter signup, footer (now also home to the email / location / phone contact info). Single primary scroll on home; event detail is a dedicated route. The same contact form also lives at **`/contact`**; hero and nav “Book an Event” link there (`CONTACT_PAGE_PATH` in `lib/site.ts`), while the home section remains scroll-targetable as `#contact`. The blog source remains in the repo but is temporarily disabled for public access: **`/blog`**, **`/blog/[slug]`**, and the blog hosts return 404 while `BLOG_PUBLIC_ACCESS_ENABLED` is `false`, and Blog is hidden from navigation, footer links, sitemap, and route crawls. Blog articles are preserved as long-form LUPFR operator essays: every article must name a specific LUPFR event or situation, speak from a first-person operator/founder angle, and state an opinionated thesis instead of generic event-marketing advice. YAML body lines may use markdown-style markers (`##`, `###`, `>`, `-`, and `**Source note:**`) that render as animated headings, subheads, pull quotes, bullets, and source-note cards with lighter, thinner prose typography sized for denser long reads. Unknown URLs use a self-contained `app/not-found.tsx` document (plain logo image and home link) so 404 responses do not depend on the normal client navigation bundle.

**Metallic gold (theme).** In `app/globals.css`, **light** (`:root`) uses a clean white surface with pure-black ink and bronzed luxe gold accents: true white page/card/popover surfaces, neutral faint-gray muted fills (no warm cream), pure-black foreground text, transparent borders, and a flat white page (no gold wash). Light headings and metric numerals use `--gradient-heading-gold`, a bronzed gold gradient (less bright/glary, keeps shine) so metal reads as luxurious bronze on white rather than bright glare. **Dark** (`.dark`) uses **white gold** (cooler, lower chroma; `--gold*` / `--btn-gold*`) and explicitly overrides `--gradient-heading-gold` to the locked black-mode white-gold recipe, so light-mode tuning must not change the near-black presentation. Hero **LUPFR**, **Entertainment**, and rotating taglines use brighter `--gradient-hero-gold` plus `--filter-hero-gold` edge/shadow so the gold highlight reads over video without reintroducing a broad background haze. Optional **Entertainment** line gradient tokens remain `--entertainment-line-*` in `:root` (white specular → polished gold). Hero **LUPFR** metallic motion: `hero-gold-shine-scroll` + periodic `hero-shine-pass` when `prefers-reduced-motion` allows. Section and page titles via **`GoldShineText`**: **`.heading-metallic-gold` + `.gold-shine-text`**; **`.gold-shine-text`** sets **`display: inline-block`** and **`overflow: visible`** in globals so **`h1`** and **`span`** get the same metallic box (avoids full-width `h1` **block** changing how the gradient reads vs inline badges).

**Metallic gold — preserve (no accidental regressions).** This is the **intended brand look**: do not swap dark mode to a different metal (e.g. **copper / bronze** low-hue sets) or drop hero shimmer without an explicit product decision. **`tests/unit/globals-gold-theme.test.ts`** asserts the canonical light `--gradient-heading-gold`, locked dark `--gold*` / `--btn-gold*` / `--gradient-heading-gold`, entertainment lines, and the presence of **`hero-shine-pass`** + **`hero-gold-shine-*`**. If you change the palette on purpose, update **`app/globals.css`**, that test, and this sentence in the same change set.

The founder **portrait is removed** (owner request 2026-07-02 — his face already appears in the Team section below): the section is condensed and text/brand-focused, and closes with the byline **“Will Lupfer — CEO & Founder of LUPFR Entertainment”** over a small muted `MapPin` office-address line (“87 N Raymond, Pasadena, CA”) at the **bottom** of the story column.

**Reviews (retired).** The scrolling testimonial marquee (`_deprecated/reviews-marquee.tsx` + `.css`) and the rotating **metrics/stats carousel** (`_deprecated/reviews-stats.tsx`) are both **archived** — the stats section (attendees etc.) was removed from the home page by owner request (2026-07-02). Its slot under the hero is now the **corporate partners strip** (`components/partners-strip.tsx`): the single-row auto-scrolling partner marquee with **no tinted band** (the `bg-muted/40 border-y` treatment was removed 2026-07-11 — the section inherits the page background entirely, pure white in light / pure dark in dark) and **no visible section text at all** — the small gold “Corporate partners” eyebrow was removed (owner request 2026-07-11); the section keeps `aria-label="Corporate partners"` for assistive tech.

**Home client bundle.** `components/home-page.tsx` keeps the first viewport immediate (`Navigation`, `Hero`, `PartnersStrip`) and mounts `Events`, `Services`, and **`Artists` eagerly** (normal imports) so tapping/clicking **Events** in nav is instant, fast scrolling from **Events** into **Services** never lands on a blank deferred placeholder, and Featured Artists stays interactive without a deferred mount. **`Press` is deferred** behind `DeferredHomeSection` (`id="news"`) plus `next/dynamic` (`ssr: false`); `About`, `Team`, `Contact`, and `Footer` stay code-split the same way with compact lazy placeholders so the primary home scroll still avoids long blank travel before later sections mount. Initial-chunk motion uses **`LazyMotion` + `domAnimation`** (non-strict) via `components/motion-provider.tsx` in `app/layout.tsx`, with shared primitives importing Framer’s lighter **`m`** API instead of the full `motion` proxy. The standalone home `#gallery` section is retired (photos live on event detail pages).

**Mobile performance (≤767px).** Goal: home usable in **~2–5s** on phone/low-compute (budgets in `tests/performance/mobile-budgets.json`). Hero uses a static grid/orbs (no continuous Motion loops), **lighter Gaussian blurs** on the static orbs than on desktop-lite/reduced-motion, longer hero phrase rotation, **`next/image` poster only** (no hero `<video>` elements — avoids ~5MB+ decode/buffer work on cellular) served from **dedicated ~1080px mobile posters** (`/hero/hero-poster-{dark,light}-mobile.webp`, <90KB each) rather than the 2560×3413 / ~700KB desktop posters, so the phone LCP hands the optimizer a tiny source instead of re-encoding a huge one (`HERO_POSTER_{DARK,LIGHT}_MOBILE` in `components/hero-shared.tsx`, used only in `components/hero-mobile-static.tsx`; desktop keeps the full posters + video), **static** metallic taglines via `GoldShineText` `variant="static"` and a static Entertainment line (no hero-level `useScroll` / parallax subtree), and a non-animated scroll hint. Below-fold home sections (`#services`–`#contact`, not `#events`/hero) use mobile-only `content-visibility: auto` with a generous intrinsic size so off-screen layout is skipped without breaking hash scroll; photo-card shimmer (`SkeletonShimmerLayer`) delays ~200ms so fast loads never flash. Both mobile poster and desktop video media share `.lupfr-hero-media-wash`, a restrained top/mid overlay with only the bottom strengthened for page transition, so the hero photo/video remains visible behind the brand lockup. `components/hero.tsx` uses **`next/dynamic`** to load **`components/hero-desktop.tsx`** only when `useIsMobile() === false` so **phone/tablet-first viewports skip downloading desktop-only chunks** (dual MP4s, orb animation loops, `useScroll`/parallax, scroll-linked `GoldShineText`). Featured Artists uses a static mobile grid with plain `next/image` cards, direct social links, no carousel controls, and no embedded music iframes. Prefers-reduced-motion for the hero uses **`hooks/use-prefers-reduced-motion.ts`** (`useSyncExternalStore`) rather than tying the shell to Framer Motion. First-load JS on phones is further reduced by deferring **Press** only (Artists stays eager) and by the layout **`MotionProvider`** (`LazyMotion` / `domAnimation`, non-strict) so initial-chunk sections pay for the lighter motion feature set. **Desktop / laptop (≥768px)** is **not** globally downgraded: when `useIsMobile() === false`, the hero still loads the desktop chunk (`preload="auto"` videos, scroll parallax, scroll-linked fade, scroll-driven title + rotating phrase shine). Top scroll progress bar is omitted (and its Framer `useScroll` subtree does not mount, avoiding extra scroll-linked work). Breakpoint matches `hooks/use-mobile.ts` (`useLayoutEffect` for earlier, pre-paint width read).

**Scroll-driven motion (flicker avoidance).** Until `useIsMobile()` resolves (`undefined`), the site treats the viewport as **not desktop-confirmed**: hero matches the **mobile** subtree (poster-only media, no hero `useScroll`) and the top scroll progress bar stays hidden. After mount, only `isMobile === false` (≥768px) mounts the **desktop** hero subtree (dual videos, parallax, scroll-linked fade + `GoldShineText` scroll variant on rotating lines), plus scroll progress. `ScrollReveal` uses one `m.div` with scroll-linked opacity/transform from the first client paint (no interim plain `div` at full opacity). Section titles and below-the-fold `GoldShineText` still use `useScroll` with `layoutEffect: false` when the measured target is a parent ref, avoiding Framer “ref not yet hydrated” warnings under Strict Mode. Desktop rotating hero taglines use `GoldShineText` with the hero `section` ref (metallic gold, not flat accent); mobile uses `variant="static"`. Phrase changes use a short vertical + blur crossfade unless `prefers-reduced-motion` (opacity only). Section **lead paragraphs** (Services, Featured Artists, Contact, About story) use **`components/text-reveal.tsx`** (`TextReveal`): a per-word staggered rise + fade (`whileInView`, `once: true`, opacity + transform only — no filter blur) with `aria-label` on the container and `aria-hidden` word spans so screen readers get one sentence; `prefers-reduced-motion` renders the static text.

**Framer / dev console.** Motion-animated colors and shadows use `rgba`/`#hex` (not `oklch()` in `animate`/`whileHover`) so Framer can interpolate. Hero video hints use `<video preload>` only (no `react-dom` `preload` with `as: "video"`—React warns). The first event card uses `next/image` `priority`/`fetchPriority` instead of root `<link rel="preload">` for the raw file path (optimizer URL would not match).

**Scroll smoothness vs flicker.** `html { scroll-behavior: auto }` keeps wheel/trackpad scrolling in sync with Framer `useScroll` (native `smooth` fights scroll-linked opacity/transform). `ScrollReveal` renders scroll-driven motion immediately—no pre-mount plain `div` at full opacity (that caused a flash when switching to opacity 0 below the fold). Body omits long `background-color`/`color` transitions so theme and scroll motion don’t compound into visible shimmer.

**Gold controls and cards (owner rollback 2026-07-08).** Key CTAs (nav **Book an Event** + **Schedule a call**, Artists **Submit Your Mix**, Events **View all reels**), **Team filter chips**, **Team cards**, and **Featured-artist cards** use the existing CSS gold button/pill styling plus `GoldCard` / `ArtistCard` behavior. Do not add animated shader/canvas wrappers or extra visual-effect package dependencies around these controls without an explicit product decision and matching performance tests; the preferred state is the pre-ring gold button design with desktop card tilt intact and mobile tilt disabled via `useIsMobile()`.
