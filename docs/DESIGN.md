# Design

**Product.** Marketing site for LUPFR Entertainment: hero, social proof (metrics carousel in the Reviews section), events list + event detail pages, services, artists, blog, about, contact form, newsletter signup, footer. Single primary scroll on home; event detail is a dedicated route. The same contact form also lives at **`/contact`**; hero and nav “Book an Event” link there (`CONTACT_PAGE_PATH` in `lib/site.ts`), while the home section remains scroll-targetable as `#contact`. The blog has a route pair at **`/blog`** and **`/blog/[slug]`** and also resolves from **`blog.localhost:3001`** / **`blog.lupfr.com`** through host-based rewrites in `proxy.ts`. Unknown URLs use a self-contained `app/not-found.tsx` document (plain logo image and home link) so 404 responses do not depend on the normal client navigation bundle.

**Metallic gold (theme).** In `app/globals.css`, **light** (`:root`) uses a pristine luxury white-and-gold palette: true white page/card/popover surfaces, platinum-gray muted surfaces, crisp charcoal foreground text, and a fixed white page wash with subtle gold light. Light headings and metric numerals use `--gradient-heading-gold`, a richer polished gold gradient with dark contrast cuts and bright specular stops so metal reads clearly on white cards instead of fading into champagne. **Dark** (`.dark`) uses **white gold** (cooler, lower chroma; `--gold*` / `--btn-gold*`) and explicitly overrides `--gradient-heading-gold` to the locked black-mode white-gold recipe, so light-mode tuning must not change the near-black presentation. Hero **LUPFR**, **Entertainment**, and rotating taglines use brighter `--gradient-hero-gold` plus `--filter-hero-gold` edge/shadow so the gold highlight reads over video without reintroducing a broad background haze. Optional **Entertainment** line gradient tokens remain `--entertainment-line-*` in `:root` (white specular → polished gold). Hero **LUPFR** metallic motion: `hero-gold-shine-scroll` + periodic `hero-shine-pass` when `prefers-reduced-motion` allows. Section and page titles via **`GoldShineText`**: **`.heading-metallic-gold` + `.gold-shine-text`**; **`.gold-shine-text`** sets **`display: inline-block`** and **`overflow: visible`** in globals so **`h1`** and **`span`** get the same metallic box (avoids full-width `h1` **block** changing how the gradient reads vs inline badges).

**Metallic gold — preserve (no accidental regressions).** This is the **intended brand look**: do not swap dark mode to a different metal (e.g. **copper / bronze** low-hue sets) or drop hero shimmer without an explicit product decision. **`tests/unit/globals-gold-theme.test.ts`** asserts the canonical light `--gradient-heading-gold`, locked dark `--gold*` / `--btn-gold*` / `--gradient-heading-gold`, entertainment lines, and the presence of **`hero-shine-pass`** + **`hero-gold-shine-*`**. If you change the palette on purpose, update **`app/globals.css`**, that test, and this sentence in the same change set.

**About.** The large horizontal text marquee that listed service phrases (boat parties, rooftop sessions, etc.) is **archived** (see `_deprecated/about-marquee.tsx`); it is not rendered on the live About section. The founder portrait uses a **light** theme with a very light bottom gradient and no side vignette (subtle `ring` only); **dark** keeps the stronger top/bottom and left/right fades into `--background`.

**Reviews.** The scrolling testimonial marquee (desktop three-layer + mobile single strip) is **archived** (`_deprecated/reviews-marquee.tsx` + `_deprecated/reviews-marquee.css`); the live section shows only the rotating metrics carousel. Metrics render as larger card tiles; on `(hover: hover)` + `(pointer: fine)` they tilt slightly toward the cursor (transform-only while the pointer moves). `prefers-reduced-motion` turns off tilt.

**Home client bundle.** `components/home-page.tsx` keeps the first viewport immediate and mounts `Events` and `Services` eagerly (normal imports) so tapping/clicking **Events** in nav is instant and fast scrolling from **Events** into **Services** never lands on a blank deferred placeholder. Lower sections (`Press`, `Gallery`, `About`, `Contact`, `Footer`) stay code-split behind `next/dynamic` and compact lazy placeholders so the primary home scroll still avoids long blank travel before later sections mount.

**Mobile performance (≤767px).** Hero uses a static grid/orbs (no continuous Motion loops), **lighter Gaussian blurs** on the static orbs than on desktop-lite/reduced-motion, longer hero phrase rotation, **`next/image` poster only** (no hero `<video>` elements — avoids ~5MB+ decode/buffer work on cellular), **static** metallic taglines via `GoldShineText` `variant="static"` and a static Entertainment line (no hero-level `useScroll` / parallax subtree), and a non-animated scroll hint. Both mobile poster and desktop video media share `.lupfr-hero-media-wash`, a restrained top/mid overlay with only the bottom strengthened for page transition, so the hero photo/video remains visible behind the brand lockup. `components/hero.tsx` uses **`next/dynamic`** to load **`components/hero-desktop.tsx`** only when `useIsMobile() === false` so **phone/tablet-first viewports skip downloading desktop-only chunks** (dual MP4s, orb animation loops, `useScroll`/parallax, scroll-linked `GoldShineText`). Featured Artists uses a static mobile grid with plain `next/image` cards, direct social links, no carousel controls, and no embedded music iframes. Prefers-reduced-motion for the hero uses **`hooks/use-prefers-reduced-motion.ts`** (`useSyncExternalStore`) rather than tying the shell to Framer Motion. **Desktop / laptop (≥768px)** is **not** globally downgraded: when `useIsMobile() === false`, the hero still loads the desktop chunk (`preload="auto"` videos, scroll parallax, scroll-linked fade, scroll-driven title + rotating phrase shine). Reviews: slower stats carousel interval, no scroll-linked section fade (full opacity). Top scroll progress bar is omitted (and its Framer `useScroll` subtree does not mount, avoiding extra scroll-linked work). Breakpoint matches `hooks/use-mobile.ts` (`useLayoutEffect` for earlier, pre-paint width read).

**Scroll-driven motion (flicker avoidance).** Until `useIsMobile()` resolves (`undefined`), the site treats the viewport as **not desktop-confirmed**: hero matches the **mobile** subtree (poster-only media, no hero `useScroll`), Reviews skips scroll-linked fade and uses the slower carousel interval, and the top scroll progress bar stays hidden. After mount, only `isMobile === false` (≥768px) mounts the **desktop** hero subtree (dual videos, parallax, scroll-linked fade + `GoldShineText` scroll variant on rotating lines), plus scroll progress and Reviews scroll fade. `ScrollReveal` uses one `motion.div` with scroll-linked opacity/transform from the first client paint (no interim plain `div` at full opacity). Section titles and below-the-fold `GoldShineText` still use `useScroll` with `layoutEffect: false` when the measured target is a parent ref, avoiding Framer “ref not yet hydrated” warnings under Strict Mode. Desktop rotating hero taglines use `GoldShineText` with the hero `section` ref (metallic gold, not flat accent); mobile uses `variant="static"`. Phrase changes use a short vertical + blur crossfade unless `prefers-reduced-motion` (opacity only).

**Framer / dev console.** Motion-animated colors and shadows use `rgba`/`#hex` (not `oklch()` in `animate`/`whileHover`) so Framer can interpolate. Hero video hints use `<video preload>` only (no `react-dom` `preload` with `as: "video"`—React warns). The first event card uses `next/image` `priority`/`fetchPriority` instead of root `<link rel="preload">` for the raw file path (optimizer URL would not match).

**Scroll smoothness vs flicker.** `html { scroll-behavior: auto }` keeps wheel/trackpad scrolling in sync with Framer `useScroll` (native `smooth` fights scroll-linked opacity/transform). `ScrollReveal` renders scroll-driven motion immediately—no pre-mount plain `div` at full opacity (that caused a flash when switching to opacity 0 below the fold). Body omits long `background-color`/`color` transitions so theme and scroll motion don’t compound into visible shimmer.

**Animated gradient ambience.** `app/layout.tsx` mounts a single fixed background layer (`components/liquid-metal-canvas.tsx`) that now renders smooth animated gold gradients (no zebra stripes, no rotating gallery-only frame). The layer is `pointer-events: none`, content stays above it via `z-index`, and motion is reduced on mobile / disabled for `prefers-reduced-motion`.

**Content-driven sections.**

- **Events:** Single ordered list from `data/events.yml` (not split into “upcoming” vs “past” sections). `dateISO` drives past vs future; `null` = TBD date, still “upcoming”. Upcoming vs past is computed at render time from `dateISO` vs today’s calendar date in `America/Los_Angeles` (string compare on `YYYY-MM-DD`). **Carousel order** within **Upcoming** is by `dateISO` ascending (soonest first); **date TBD** rows (`dateISO` null) sort last. **Past** is newest `dateISO` first. Hero images use the `/events/...` path namespace in YAML. Each event: image, title, subtitle, date, time, location, optional ticket link + optional **`ticketLabel`** (gold CTA on **`/events/[slug]`** defaults to **Tickets** when omitted), optional **`contentLinks`** (`label` + `url`) rendered on the event detail page for post-event photo/video/drone folders, description. Card links use **`components/event-detail-link.tsx`** and canonical **`eventDetailPath`** URLs; event detail routes are prefetched after the carousel mounts and again on focus/hover/touch, while touch/click sets `data-pending="true"` immediately for visible mobile feedback. Card badge: **Past Event** and **Upcoming Event** (future or date TBD) use **`GoldShineText`** as a **`span`** inside an **`h4`** in the frosted pill (`.heading-metallic-gold` + `.gold-shine-text`, scroll target = Events **`section`**), matching section titles; **Today's Event** uses **accent** on the **`h4`**; the home Events section re-evaluates on a short interval so labels and Upcoming/Past carousels can update after midnight without reload. Event detail uses the same client badge; the **hero** pill uses **`text-base` / `sm:text-lg`** so the label reads at a small-heading scale (home cards use **`text-sm`** in the pill). Detail page at `/events/[slug]` shows the **full hero/poster** (`object-contain`, capped by viewport height) so flyers are not cropped like the home cards. **`generateMetadata`** on the detail route sets Open Graph / Twitter **`summary_large_image`** using the YAML hero and title; **`components/gallery-share-row.tsx`** (same controls as gallery: native share, X, Facebook, LinkedIn, Instagram profile link, copy URL) sits below the body with share text built from **`eventShareTitle`** (`title` + optional `subtitle`) in `lib/events.ts`. The Events block uses `ScrollReveal` with `freezeAfterReveal` so scroll-linked opacity does not fade the carousels out when leaving the section (avoids card flashing). In-view animations for cards use a one-way `hasRevealed` latch so leaving the intersection observer does not reset Framer `animate` to hidden. 3D tilt and image zoom run only for `(hover: hover)` and `(pointer: fine)`; image area keeps `bg-muted` under the photo to reduce loading flash.
- **Gallery (home photo carousel + full gallery):** From `data/gallery.yml`. The modal lightbox (`GalleryLightbox`) and the shareable **`/gallery/p/[id]`** hero (`GalleryPhotoHero`) keep a **sliding window**: hidden eager `next/image` loads for **±1…±N** neighbors (see `GALLERY_SLIDING_PRELOAD_RADIUS` in `lib/gallery-nav.ts`; N=2 today so up to two steps each direction, deduped: `galleryCircularPreloadIndices` in the lightbox, `galleryLinearPreloadIndices` on the shareable page) so the next few prev/next clicks are usually already decoded. The home carousel auto-advances continuously and should keep rotating after manual controls/swipes. On laptop/desktop (`>=768px`, motion-safe), the home `#gallery` block adds a subtle **cinematic frame** treatment: ambient liquid-gold blobs behind the section, a slow border sheen on the carousel frame, and gentle scroll-linked frame/media transforms (tiny parallax + zoom) for a modern premium feel; mobile and reduced-motion stay on the static baseline. The **photo-page hero** uses a fixed **8:5** frame (`aspect-[8/5]`, `max-h` roughly **82dvh / 1200px** on large viewports) and **in-frame** `object-contain` images so copy below the frame does not **jump** when the current photo decodes. The lightbox image strip uses the same idea (`aspect-[16/10]`). The visible slide (and **carousel positions outside the current decode ring** on large home carousels) sit over **`.skeleton-shimmer`**, not a flat muted gradient, until the slide mounts a real `next/image` and **fades in** after load (reduced-motion short-circuits the sweep). The home carousel **switches** between a shimmer-only + hit-target branch and a decoding branch so re-entering the ring remounts decode state and cached images do not skip the underlay. Raster sources are **WebP** under `public/gallery/`; Next `images.formats` may serve AVIF/WebP from the optimizer. The **`/gallery` link grid** (`components/gallery-photo-grid.tsx`) and the **lightbox masonry** thumbs use **square tiles** (`aspect-square`) with **squircle-style** clipping: `rounded-gallery-squircle` in `app/globals.css` (clamped `border-radius` token, plus `corner-shape: squircle` inside `@supports` for Chromium) plus an inset `ring` and soft `shadow`. While **photo and raster cards** load (event list/detail posters, artist cards, partner logos, about portrait, **nav / footer / 404** wordmark via `components/lupfr-logo-image.tsx`, **hero** static poster when the inline video path falls back to still, home gallery carousels, **`/gallery` grid** tiles, lightbox, masonry thumbs, and **`/gallery/p/[id]`** hero), **`.skeleton-shimmer`** (muted radial base + gold sweep via **`shimmer-sweep`**) shows underneath; after `onLoad` the image **fades in** (`prefers-reduced-motion`: sweep disabled). The **`.gallery-grid-tile-placeholder`** class name is an alias to the same rules for backward compatibility. Gallery frames use **`rounded-gallery-squircle`** where applicable; other cards inherit radius from the parent. Non-image `components/ui/skeleton.tsx` pieces keep **pulse** (text-line placeholders only). Hover uses transform-only image scale with `motion-safe` / `motion-reduce` fallbacks. Image paths use `/gallery/...` (files under `public/gallery/`). The first directory under `public/gallery/<folder>/` defines the **album** for grouping and the home carousel jump control. **Breadcrumbs** after **Event pics** show each **URL path folder** under `gallery/…` (e.g. `Event pics / boiler_boat_003`; nested folders add more segments). Human **labels** (headings, jump buttons) still use the event **`title` from `data/events.yml` via `GALLERY_ALBUM_FOLDER_DEFAULT_DATES` in `lib/data/gallery.ts` (optional YAML `album` on a row overrides). **`GALLERY_HOME_ALBUM_FOLDERS`** lists which albums get a **grid block** on the home page below the carousel (see `lib/data/gallery.ts`). Each photo has **`dateISO`** (`YYYY-MM-DD`): optional per-row YAML `date`, else **`GALLERY_ALBUM_FOLDER_DEFAULT_DATES`** (aligned with `data/events.yml` dates). YAML `image` paths must match real directories (e.g. `boiler_boat_003`, `where_is_west`). **`lib/gallery-date.ts`** formats labels like Apple Photos (e.g. `Apr 4, 2026`) and groups **`/gallery`** into date sections (newest day first; missing dates under **Undated**). Optional per-row `showOnHome: false` keeps a row off the home carousel (still in the full grid). The carousel is **not** the same as the events list. **Routing:** the home carousel section uses DOM id **`#gallery`** (scroll target; primary nav **Gallery** uses **`/#gallery`**). The dedicated route **`/gallery`** lists every YAML row as a **link grid** (`components/gallery-photo-grid.tsx`, `dateSections` default **true**): tap goes to **`/gallery/p/[id]?from=gallery`**. The live home page (`components/gallery.tsx`) makes the **full slide** (image through caption) one link to **`/gallery/p/[id]?from=home`**. **Below `md` (768px)**, home carousel slide overlays are **minimal**: **photo title only** (breadcrumb, date, YAML caption, and the “tap to open full page” hint are hidden); **`components/gallery-section.tsx`** uses the same rule so album grids match. From **`md`** up, the full overlay stack returns. so **Back to home** / **Escape** return to **`/#gallery`**, not **`/gallery`**. On primary click from **`/`** when the hash is not already **`#gallery`**, **`homeHistoryReplaceForGalleryBack`** rewrites the current history entry to **`/#gallery`** so **browser Back** also returns to the gallery section instead of bare **`/`**. `components/gallery-section.tsx` renders per-album grids with **`dateSections: false`** so the section title shows the date once. **`/gallery/p/[id]`** is the shareable page (Open Graph / Twitter `summary_large_image`, `GalleryEventBreadcrumb`, `components/gallery-share-row.tsx` — **icon + label** chips for Share, X/Twitter, Facebook, LinkedIn, Instagram profile, copy link). Layout is **image-first**: the hero frame sits directly under the back link, with **`max-h` capped by `dvh`/`vh`** and `object-contain` (similar spirit to event-detail posters). **Previous / next** are **circular chevron controls** overlaid at the horizontal midline of the frame (not a separate top pill row); copy and metadata sit **below** the image. Instagram has no one-click “post this URL to feed” on the web—copy-link + paste in app is documented on the photo page.
- **Artists:** From `data/artists.yml`. Card: image, name, genre, bio, social links (Spotify, Apple Music, Instagram, etc.), optional featured track as a native lazy-loaded Spotify or SoundCloud iframe. Spotify embeds force dark player chrome (`theme=0`), and SoundCloud uses the compact non-visual player so music widgets do not change layout or visual mode between light and dark themes.
- **Services:** From `data/services.yml`. Display as defined in YAML (e.g. titles, descriptions, icons).
- **Partners:** From `data/partners.yml`; corporate row renders in `components/services.tsx` via `getPartners()`. Logos use a **responsive grid** (`grid-cols-2` / `sm:grid-cols-4`, `place-items-center`); each link is a fixed **`size-*` circle** with **`bg-card`**, **`border-2`**, `overflow-hidden`, and theme-specific **`.partner-logo-chip`** shadow (see `app/globals.css`). Mono marks use `.partner-logo`: **light** ≈ black ink on the card; **dark** ≈ softened white via `invert` + `brightness(0.93–0.94)` with opacities from `--partner-logo-opacity*`. Optional YAML `imageClassName` (e.g. `scale-[0.9]`) normalizes visual weight. Optional `logoTreatment`: `outline`, `solid`, `natural` (full-color, per-theme `brightness`/`saturate` tweaks). Use **`natural`** when the PNG is mostly a flat-filled shape (e.g. circular brand mark with gradient)—mono `brightness(0)` would render as a solid blob.

**Layout containment.** Every section/nav `container` wrapper carries an explicit width cap — default **`max-w-7xl`** (1280px), narrower where intentional (gallery `max-w-6xl`, careers `max-w-5xl`, legal `max-w-2xl`, event detail `max-w-4xl`) — because Tailwind v4's bare `container` only caps at the raw breakpoint (1536px) and would render nearly edge-to-edge on ~1440–1600px viewports. New sections must pair `container mx-auto` with a `max-w-*` cap so all content shares the same centered margins. Full-bleed surfaces (hero media, reviews marquee) are the deliberate exceptions.

**UI/UX.** Fonts: Space Grotesk (sans), Inter (body), Playfair Display (serif). **Heading scale (in `app/globals.css`):** Inside **`<main>`**, **`h1` / `h2`** get the default marketing display scale (serif, responsive `text-3xl` → `text-7xl`); **`.lupfr-heading--compact`** on those tags reduces the **md/lg** step for About and Corporate partners. **Stacked two-line** titles (gold first line + ink/white second) use **`GoldShineText`** on line 1 and **`.lupfr-heading-subline`** on line 2 (color token **`--lupfr-heading-subline-fg`**: near-black ink in light mode, `.dark` overrides to theme **`foreground`** white — sublines like “Artists”/“Partners” stay high-contrast in both themes); block spacing uses **`.lupfr-heading-stack`** (generous) or **`.lupfr-heading-stack--tight`** (About-style); titles embedded in a horizontal flex use **`.lupfr-heading-split-leading`** for the same **`line-height: 1.08`** without extra block margins. Optional softer tertiary line: **`.lupfr-heading-subline--soft`**. **Subsection** titles that use the gold shine use **`h3` + `.lupfr-heading-sub`** (or **`GoldShineText` `as="h3"`** with that class). **Eyebrow** lines above a block use **`.lupfr-heading-eyebrow`**. The **hero** root is **`lupfr-hero`**: hero `h1` keeps **`hero-title-lupfr`** / **`hero-gold-shine-*`** and is not meant to be restyled by the main heading rules beyond margin reset. **Typography:** marketing UI uses **sentence case** and normal or tight letter-spacing—no `uppercase` / wide-tracked “poster” styling on nav, hero CTAs, footer, form labels, or section eyebrow lines (brand acronym **LUPFR** in source stays as-is). Pill CTAs (`.btn-metallic-gold` / `.btn-metallic-brass` and the hero outline pair) keep label text on **one line**; `--lupfr-pill-cta-fs` in `app/globals.css` uses a `clamp()` so type scales down on narrower viewports instead of wrapping. The **desktop** fixed header (≥`lg`) aligns **section links**, the outline **Schedule a call** (`size` sm), and **Book an Event** on the same **text-sm** / **font-medium** line with **h-9** controls so the bar does not mix multiple sizes. **Book a call:** Google Calendar booking URL is `LINKS.scheduleCall` in `lib/links.ts` (LUPFR Calls). The **Schedule a call** CTA is a single shared outline pill with calendar icon (`components/schedule-call-cta.tsx`): `tone` **on-dark** (hero, nav over media) or **on-surface** (footer, scrolled nav, mobile drawer), `size` **sm** (desktop nav) or **md** (hero, mobile, footer). **on-dark** uses theme **`foreground`** and **`border-foreground/30`** (not hardcoded `text-white` in light mode) so outline pills stay legible on the light hero video; dark theme `foreground` remains light. The hero **Watch Reel** outline control uses the same pattern. It appears in the hero, desktop nav, mobile drawer, and footer under the email. Theme support via `ThemeProvider` (next-themes). **Global Escape (back).** `components/escape-back.tsx` listens for the Escape key and calls `router.push` to the same target as the page’s main back link (`lib/escape-back.ts`, e.g. event detail `/#events`, photo page `/gallery` or `/#gallery` per `?from=`, full gallery `/#gallery`, legal and `/contact` `→ /`). It does not run when focus is in a form control, or when the mobile nav drawer, contact-list modal, or a Radix `Dialog` is open (so those layers still consume Escape first). **Navigation** (`components/navigation.tsx`): fixed bar stays above the mobile full-screen drawer (`z-[60]` vs `z-[55]`); no Framer entrance on the bar (avoids fighting `transition-all` scroll styling). **`html { scroll-padding-top }`** in `app/globals.css` uses **`--lupfr-fixed-header-scroll-padding`** (aligned with the scroll-spy offset) so in-page **`#events` / `#services` / `#artists` / …** land below the header instead of under it. **Route changes:** primary `Link`s use `prefetch` where applicable; desktop/mobile nav links use `initial={false}` so link rows do not replay a staggered mount animation on every page (faster perceived return to home). **`PrefetchHomeRoute`** in `app/layout.tsx` calls `router.prefetch("/")` on subpages so `/` RSC/JS warm while the user is still on gallery, event detail, etc. Mobile drawer locks `html`/`body` overflow while open, closes on `Escape` or backdrop click, uses safe-area padding and scrollable inner nav; section highlight on home uses a scroll-spy: the section that **contains** the offset line below the header, else fallback to the last in-page section whose top has crossed that offset. The hamburger control uses a 44×44px touch target; `data-lupfr-nav-menu-open` on `<header>` lets `EscapeBack` know not to fire while the drawer is open. **At `lg` and up (≥1024px)**, the bar is a single row: **CSS grid** `minmax(0,1fr) / auto / minmax(19rem,1.15fr)` so the **logo** stays **start**-aligned in the first column, **section links** sit in a narrow **auto** column (geometrically **centered** in the `container`), and **CTAs** are **end**-aligned in the third column (the right track’s **19rem** floor keeps the theme toggle, **Schedule a call**, and **Book an Event** from overlapping); the link row uses a semantic `ul` (`flex-wrap`, `justify-center`, `min-w-0`, per-link `whitespace-nowrap`; `gap` steps `gap-x-3` → `2xl:gap-x-8`). **Below `lg`**, the full-width inline link row is hidden and the hamburger + drawer is used (tablet/small-laptop width no longer shows an overcrowded three-column bar). Logo height still steps at `md`/`lg`/`xl` breakpoints. Desktop nav link highlights update on scroll via `requestAnimationFrame`-coalesced handlers. When the drawer is the primary nav, the theme toggle sits in the fixed header beside the menu control. The menu/close icon uses `text-foreground` while the drawer is open (or when the header is scrolled) so the X stays visible on the light overlay in light mode. On the home hero with a **transparent** header, **light** mode uses **foreground** for the desktop section links and the hamburger; **dark** mode uses **white** until the header shows the scrolled glass bar, then foreground like light when scrolled. Toasts (sonner) for form feedback. Contact and newsletter forms post to API routes; success/error surfaced in UI. Contact **inquiry type** chips include Book an Event, Corporate Event, Talent Booking, Submit Your Mix, Venue Partnership, Private Event, Sponsorship, and Other (`components/contact.tsx`).

**Cookies and consent.** `lib/legal-copy.ts` holds full **Privacy & cookies** copy (`PRIVACY_AND_COOKIES_COPY` on `/privacy`) and a shorter **`PRIVACY_AND_COOKIES_BANNER_COPY`** for the compact bottom `components/cookie-consent.tsx` rectangle, plus **Terms** copy on `/terms`. The notice uses the theme `card`, `foreground`, `muted-foreground`, and `border` tokens so it stays legible in light and dark mode; it shows the banner line and links to **`/privacy`** and **`/terms`** (no terms paragraph in the notice) until the user clicks **Accept**, which sets `localStorage` key `lupfr_cookie_consent` and a small first-party cookie, then dispatches `lupfr:cookie-consent`. **Vercel Analytics** (`components/deferred-analytics.tsx`) loads only after consent plus idle scheduling. **Contact-list preference cookies** (`lupfr_phone_popup_*`) are set only after consent; **localStorage** for the same keys is still written so dismiss/join state works before accept. API rate limiting for `/api/phone-list` remains **IP-based** in `lib/rate-limit.ts`. The footer only links to **`/privacy`** and **`/terms`** (no long legal copy in the footer).

**Contact list (phone list) → Google Sheets.** The **popup** collects **name + phone** only. Footer and contact section forms may collect name with email and/or phone, then all paths `POST` to `app/api/phone-list/route.ts`. The server forwards a JSON body to a **Google Apps Script** web app URL configured in Vercel as `GOOGLE_SHEETS_WEBHOOK_URL` (see [DEPLOYMENT.md](./DEPLOYMENT.md)); the browser never holds that URL. Operational setup and the exact JSON fields are documented there.

**Assets.** Raster photos under `public/` (except `favicon/`, `logos/`) are standardized to **WebP**; YAML uses site-root paths (e.g. `image: "/artists/name.webp"`). Social previews: `app/opengraph-image.tsx` and `app/twitter-image.tsx` generate PNGs (Satori) with the brand logo from `public/logos/will_logo.png`, wordmark line, and tagline; metadata and JSON-LD live in `app/layout.tsx`.

**SEO.** Shared defaults live in `app/layout.tsx` (`metadataBase`, default Open Graph / Twitter, JSON-LD). Each public route sets **`metadata.alternates.canonical`** to **`SITE_URL`** plus path (`lib/site.ts`). One primary **`h1`** per URL (hero on `/`, headings on gallery / events / legal; **`/contact`** uses a screen-reader **`h1`** with the page title because the shared contact block opens with **`h2`**).

**Navigation header veil.** The fixed header uses **`.lupfr-site-header`** plus `data-lupfr-nav-state="hero|settled"` in `components/navigation.tsx`. Its surface is a masked top-to-transparent gradient with very subtle gold radial wash and backdrop blur, not a flat `bg-background/*` band or hard bottom border; this keeps the bar readable while blending into the hero and page sections without visibly washing the hero media. The `nav` content stays on a relative `z-10` layer above the pseudo-element veil.

**Light theme color correction.** The light theme intentionally uses true white surfaces, platinum-gray muted/border/input/sidebar tokens, richer polished gold accents, and strong charcoal text. Do not push `:root` backgrounds toward beige/cream or reduce text contrast; the gold should read as crisp polished metal on clean white, not as a pale champagne wash or stain on the surface. Dark mode keeps the existing white-gold treatment.

**Accepted light mode baseline.** The current light mode is canonical: true white page/card/popover surfaces (`oklch(1 0 0)`), charcoal foreground text (`oklch(0.11 0.016 265)`), platinum-gray muted/border surfaces, and richer polished gold (`--gold: oklch(0.64 0.17 82)`) with darker cuts and bright specular stops in `--gradient-heading-gold`. Preserve this exact white/gold read for metrics, headings, hero Entertainment text, and gold CTAs unless a future release explicitly changes the brand palette. Any deliberate palette change must update `app/globals.css`, `tests/unit/globals-gold-theme.test.ts`, this document, and `docs/TESTING.md` in the same commit.

Light-mode section surfaces should stay minimal and cohesive: avoid beige-tinted blocks under the metrics carousel, keep the Reviews strip near-white (`bg-background` family), and use subtle glass-white stat cards with restrained neutral shadows so hierarchy stays clean without color noise.
