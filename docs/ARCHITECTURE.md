# Architecture

**High-level.** Single Next.js app (App Router). Static/semi-static pages driven by generated JSON; three API routes (`contact`, `newsletter`, `phone-list`). No database; no auth. The public build/verification gate is `bun run test`; internal build plumbing compiles YAML → JSON, then runs `bunx --bun next build` (default Turbopack; see `docs/DEPLOYMENT.md` for why the old `--webpack` pin was dropped).

**Layers.**

- **Data:** `data/*.yml` (source of truth) → `scripts/generate-data.js` → `lib/data/generated/*.json`. Re-exported via `lib/events.ts`, `lib/gallery.ts`, `lib/data/artists.ts`, `lib/data/services.ts`, `lib/data/partners.ts`, `lib/data/team.ts` (each member now carries `teams: [LA|SF|Exec]` for the Team filter boxes and an optional `image` — omitted while a portrait is pending), `lib/data/reels.ts` (`data/reels.yml`: Instagram recap-video links for the Events **Reels** block), `lib/data/blog.ts` for type-safe consumption. `scripts/optimize-public-raster.mjs` enforces **WebP** for photos in `public/` (excluding `favicon/`, `logos/`); `bun run test` runs the check. `data/events.yml` is a **single** events list: upcoming vs past is computed at runtime from `dateISO` (see `lib/events.ts`); event hero image paths in YAML are canonical `/events/...` URLs backed by files in `public/events/`. The home **gallery** carousel and per-album home sections are **retired** (owner request 2026-07-02; archived as `_deprecated/gallery-home-carousel.tsx` / `_deprecated/gallery-home-album-section.tsx`) — photos now surface on each **event detail page** via `getGalleryPhotosByDateISO(event.dateISO)` in `lib/data/gallery.ts`. That module attaches **`dateISO`** per row (optional YAML `date`, else `GALLERY_ALBUM_FOLDER_DEFAULT_DATES`) and resolves album **labels** to the matching event **`title`**; `lib/gallery-date.ts` formats labels and groups the **`/gallery`** grid by day. The full archive route **`/gallery`** (`app/gallery/page.tsx`) and per-photo pages **`/gallery/p/[id]`** (`app/gallery/p/[id]/page.tsx`) stay live so shared URLs keep working (Gallery is no longer linked from nav/footer) and use link navigation with optional `?from=` for back targets; `components/gallery-photo-grid.tsx` is the shared grid, reused by the event-page **Event gallery** block. The blog uses `data/blog.yml` with preserved static page source at `/blog` and `/blog/[slug]`; public access is disabled while `BLOG_PUBLIC_ACCESS_ENABLED` is `false`, so those routes and blog hosts return 404 and sitemap/route crawls exclude blog URLs. Image paths use `/gallery/...` (`public/gallery/`), separate from event heroes; `next.config.mjs` rewrites legacy `/gallery/boiler_boat/...` and `/events/boiler_boat_003/...` to `public/gallery/boiler_boat_003/`, and `/gallery/where_is_west_004/...` to `public/gallery/where_is_west/`. Featured artists are ordered in `data/artists.yml`; `components/artists.tsx` paginates them into carousel slides of six cards so the first slide can hold the requested front lineup while supporting additional artists. Carousel navigation/dot controls live in `components/ui/carousel.tsx` and are reused by Events and Artists.
- **Drive-as-CMS gallery (live albums):** `/gallery` additionally renders **Drive-backed event albums** (`components/drive-gallery-albums.tsx`) fed by `lib/drive-gallery.ts` from the **public** Google Drive folder `LUPFR GALLERY/website/<event_folder>/` (root folder id `DRIVE_GALLERY_ROOT_FOLDER_ID`, anyone-with-link). Listing uses Drive's anonymous `embeddedfolderview` HTML (no API key, no secret); the parser (`parseDriveFolderEntries`) is fixture-tested. Photos serve directly from Google's image CDN (`lh3.googleusercontent.com/d/<fileId>=w<width>`) through `next/image` (remotePattern in `next.config.mjs`); videos embed Drive's `/file/d/<id>/preview` player lazily. Listings are **ISR-cached** (`DRIVE_GALLERY_REVALIDATE_SECONDS`, 1 h; page `revalidate = 3600` in `app/gallery/page.tsx`), so a non-technical operator can add/replace/remove media in Drive and the site **inherits the change without a commit or deploy** — and the repo stays free of heavyweight binaries (faster builds, CDN-hosted assets). Drive subfolder names map to site album folders via `DRIVE_FOLDER_TO_ALBUM_FOLDER` so headings reuse event titles from `data/events.yml`; **unmapped** Drive folders still render with a humanized title, so new event albums appear with zero code changes. Files one nested level down (e.g. a `PHOTOS/` subfolder) are included. On any fetch/parse failure the module logs and returns `[]` — the section hides and `/gallery` degrades to the committed grid. Operator steps: `docs/RUNBOOK.md` § "Gallery media via Google Drive".
- **UI:** `app/` (routes, layout, metadata), `components/` (sections and UI). Home is a single scroll of sections (Navigation, Hero, PartnersStrip, Events (incl. the Reels block), Services, Artists, Press, About, Team, Contact, Footer — the Reviews stats section and the home Gallery section are retired), with global `PhoneListPopup` and deferred analytics mounted in `app/layout.tsx`. Event detail at `app/events/[slug]/page.tsx`. Blog index/detail source remains at `app/blog/page.tsx` and `app/blog/[slug]/page.tsx`, but public rendering is guarded by `BLOG_PUBLIC_ACCESS_ENABLED`. Dedicated contact route at `app/contact/page.tsx` (same `Contact` section as home `#contact`; “Book an Event” CTAs use `CONTACT_PAGE_PATH` in `lib/site.ts`).
- **API:** `app/api/contact/route.ts` (POST, form → Resend), `app/api/newsletter/route.ts` (POST, email → Resend; sends internal notification + welcome to subscriber), `app/api/phone-list/route.ts` (POST, name + email + phone → Google Sheets webhook).
- **Docs URL guard:** `proxy.ts` (Next.js 16; Node runtime) blocks docs-like HTTP paths (`/docs`, `/_docs`, subpaths, and several bare `/*.md` names) with **404** and `X-Robots-Tag: noindex, nofollow, noarchive`. The same proxy currently blocks `/blog`, `/blog/*`, and non-asset blog-host traffic with **404** while public blog access is disabled. Internal specs remain in repo `docs/*.md` (Git only, not `public/` or `app/docs`). `bun run test` re-checks key URLs after production build so this cannot silently break. **Unmatched routes** use the self-contained `app/not-found.tsx` route so crawlers and the verify script get a real **404** status without relying on Next's experimental global 404 manifest.
- **SEA // SIDE microsite:** `app/seaside/page.tsx` (metadata + `next/font` Anton/Inter variables) renders the self-contained client component `components/seaside/seaside-landing.tsx` — a faithful port of the SEASIDE brief design comp (hero, concept, editions carousel, featured artists, partners, team, about, request-access/partner modal). It ships its **own** nav/footer and scoped `.ss-root` styles (no LUPFR chrome, no Tailwind; motion uses **framer-motion** via `LazyMotion`/`domAnimation` + `m.*` — scroll reveals, hero parallax, modal/crossfade transitions, all gated on `useReducedMotion` — see the SEA // SIDE paragraph in `docs/DESIGN.md`). Served publicly at **`seaside.lupfr.com`** via `rewriteSeasideHost` in `proxy.ts` (clone of the blog host rewrite: `seaside.lupfr.com`, `dev.seaside.lupfr.com` (dev-branch staging), and `seaside.localhost` rewrite `/x` → `/seaside/x`, skipping `/_next`, `/api`, `/seaside/*` assets, and the shared exact-skip set). Photos/logos are WebP under `public/seaside/`; the modal posts `{ name, email }` to the existing `/api/phone-list` (access/partner intent folded into `name`); `SEASIDE_HOST`/`SEASIDE_URL` live in `lib/site.ts`; the global `PhoneListPopup` suppresses itself on `seaside.*` hosts. Domain attachment is a one-time dashboard step (see `docs/DEPLOYMENT.md`).
- **Email:** Resend client in `lib/resend.ts`; templates in `lib/email-templates`. Requires `RESEND_API_KEY` in env. Contact uses fixed `CONTACT_FORM_TO_EMAIL` (`will@lupfr.com`); newsletter internal copy uses `RESEND_TO_EMAIL` (optional env override).

**Event authoring modes.** Every row in `data/events.yml` follows one of two modes, determined by which fields are present:

- **Local mode** (default): all content is stored in the YAML row. `image` points to a file under `public/events/` (e.g. `image: /events/my_event.webp`); `ticketLink` is a direct Eventbrite/external URL; `description`, `title`, `subtitle`, `time`, `location`, `date`, and optional `contentLinks` are all authored in YAML. The build pipeline compiles this to `lib/data/generated/events.json` at build time — no runtime fetches. This is the stable, offline-capable path and must always work without network access.

- **Partiful mode** (dynamic): a single `partifulLink` field (e.g. `partifulLink: https://partiful.com/e/<id>`) makes Partiful the source of truth. The event poster image is served from Partiful's CDN (resolved at runtime), the ticket/RSVP button points to the Partiful URL, and the event description is fetched from Partiful. The YAML row still carries `id`, `slug`, `title`, `dateISO`, `date`, `time`, and `location` as fallback anchors (used for sorting, SEO metadata, and SSR skeleton). When `partifulLink` is present, `image`, `ticketLink`, `ticketLabel`, and `description` in YAML are ignored at render time; the Partiful-fetched values win. This allows adding an event to the carousel with a single URL — no local asset management needed.

  Both fields can coexist: if `image` is also set on a Partiful-mode row, it is used as the static fallback image in the carousel card (which renders at build time); the Partiful-fetched image then takes over on the detail page. A row with neither `image` nor `partifulLink` shows a gradient placeholder in the card and no hero on the detail page — valid but visually sparse.

**Invariants.**

- Content is edited via YAML + images only; component code stays stable for content updates.
- API routes enforce explicit validation and in-memory rate limiting before processing requests.
- Contact/newsletter API routes depend on Resend; missing key returns 500 with explicit error message (no silent fallback).
- No server-side secrets or user data beyond what’s needed for sending email / forwarding phone leads to Google Sheets; no in-app persistence of form payloads.

**Home performance.** `components/home-page.tsx` keeps the first viewport immediate (`Navigation`, `Hero`, `PartnersStrip`) and mounts the `Events` and `Services` sections eagerly so `#events` navigation, first event-card interaction, and the scroll boundary into Services are instant instead of waiting on a deferred placeholder. Lower sections (`About`, `Team`, `Contact` + `Footer`) remain deferred behind intersection-observed anchor placeholders, with `Press` still deferred after Artists. Deferred section loaders resolve named exports through `lib/dynamic-component.ts`, so a renamed or missing section export throws a source-specific error instead of handing React lazy an undefined element type. `PartnersStrip` is intentionally a normal import because it renders immediately below the hero; this avoids browser warnings from a preloaded dynamic chunk that is not consumed quickly enough during initial load. Mobile uses a much smaller lazy-load margin than desktop so phones do not fetch lower-section bundles several screens early. The placeholders preserve hash navigation targets before the dynamic chunks mount; matching `location.hash` mounts the requested section immediately and re-aligns to the mounted element after lazy content replaces the placeholder. Deferred lower-section mounts only realign when the current hash still points to that same lower section, so scrolling past `#events` cannot be pulled back upward by About/Team/Contact hydration. Artist music embeds render as local buttons first and only create Spotify/SoundCloud iframes after an explicit visitor tap on desktop; mobile Featured Artists renders a static image-card grid with direct social links and no player iframes. Event detail metadata/page rendering uses request-scoped memoization for Partiful fetches, and the Partiful fetch path has a short timeout with YAML fallback so remote slowness cannot stall event-detail navigation. Scroll stability is part of the home contract: the body gradient uses normal scrolling instead of `background-attachment: fixed`, the fixed navigation veil avoids `backdrop-filter`, section reveals are one-time in-view transforms instead of continuous scroll observers, and metallic heading shine is static by default.

**Hero media performance.** `components/hero-desktop.tsx` keeps optimized real-event WebP posters mounted for the active resolved theme — theme-dependent poster/video srcs go through `useHeroTheme()` in `components/hero-shared.tsx`, which resolves **dark** on the server and the first client render (`useSyncExternalStore` hydration gate) before swapping to the visitor's stored theme, so SSR HTML and hydration markup always match (no `next/image` src hydration mismatch) — and plays the optimized real ERIA Marina event loop from `public/hero/hero_event_eria_marina.mp4` on desktop. Hero posters rely on `next/image` priority rather than manual raw-file `<link rel="preload">` tags, so the browser preloads the image URL it actually consumes. If the active video cannot become playable quickly, the poster remains as the fallback. `next.config.mjs` applies immutable cache headers to `/hero/*` media so repeat visits do not revalidate hero assets. Font stacks are declared in `app/globals.css` instead of `next/font/google`, keeping production builds independent of remote Google font fetches.

**Build tooling.** `next.config.mjs` includes a production-only fallback manifest plugin for `next start` compatibility; the plugin is intentionally skipped during `next dev` because dev Webpack emits its own `pages-manifest.json` assets. `scripts/ci.sh` runs production verification in an isolated `NEXT_DIST_DIR` under `.next-ci/` so CI does not delete active dev caches.
