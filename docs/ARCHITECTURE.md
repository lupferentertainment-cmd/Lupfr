# Architecture

**High-level.** Single Next.js app (App Router). Static/semi-static pages driven by generated JSON; three API routes (`contact`, `newsletter`, `phone-list`). No database; no auth. Build step compiles YAML → JSON, then `bunx --bun next build --webpack` (see `package.json` `build` script).

**Layers.**

- **Data:** `data/*.yml` (source of truth) → `scripts/generate-data.js` → `lib/data/generated/*.json`. Re-exported via `lib/events.ts`, `lib/gallery.ts`, `lib/data/artists.ts`, `lib/data/services.ts`, `lib/data/partners.ts` for type-safe consumption. `scripts/optimize-public-raster.mjs` (see `bun run public:images:check` / `public:images:optimize`) enforces **WebP** for photos in `public/` (excluding `favicon/`, `logos/`); pre-commit and CI run the check. `data/events.yml` is a **single** events list: upcoming vs past is computed at runtime from `dateISO` (see `lib/events.ts`); event hero image paths in YAML are canonical `/events/...` URLs backed by files in `public/events/`. The home **gallery** carousel (`components/gallery.tsx`, section id `#gallery`) is a subset of `data/gallery.yml` (rows with `showOnHome` not `false`). `lib/data/gallery.ts` attaches **`dateISO`** per row (optional YAML `date`, else `GALLERY_ALBUM_FOLDER_DEFAULT_DATES`) and resolves album **labels** to the matching event **`title`**; `lib/gallery-date.ts` formats labels and groups the **`/gallery`** grid by day. The full archive route **`/gallery`** (`app/gallery/page.tsx`) and per-photo pages **`/gallery/p/[id]`** (`app/gallery/p/[id]/page.tsx`) use link navigation and optional `?from=` for back targets; `components/gallery-photo-grid.tsx` is the shared grid. **`components/gallery-section.tsx`** is an alternate home layout that adds **per-album** grids under the carousel for `GALLERY_HOME_ALBUM_FOLDERS`. Image paths use `/gallery/...` (`public/gallery/`), separate from event heroes; `next.config.mjs` rewrites legacy `/gallery/boiler_boat/...` and `/events/boiler_boat_003/...` to `public/gallery/boiler_boat_003/`, and `/gallery/where_is_west_004/...` to `public/gallery/where_is_west/`. Featured artists are ordered in `data/artists.yml`; `components/artists.tsx` paginates them into carousel slides of six cards so the first slide can hold the requested front lineup while supporting additional artists. Carousel navigation/dot controls live in `components/ui/carousel.tsx` and are reused by Events and Artists.
- **UI:** `app/` (routes, layout, metadata), `components/` (sections and UI). Home is a single scroll of sections (Navigation, Hero, Reviews, Events, Services, Artists, Gallery, About, Contact, Footer), with global `PhoneListPopup` and deferred analytics mounted in `app/layout.tsx`. Event detail at `app/events/[slug]/page.tsx`. Dedicated contact route at `app/contact/page.tsx` (same `Contact` section as home `#contact`; “Book an Event” CTAs use `CONTACT_PAGE_PATH` in `lib/site.ts`).
- **API:** `app/api/contact/route.ts` (POST, form → Resend), `app/api/newsletter/route.ts` (POST, email → Resend; sends internal notification + welcome to subscriber), `app/api/phone-list/route.ts` (POST, name + email + phone → Google Sheets webhook).
- **Docs URL guard:** `proxy.ts` (Next.js 16; Node runtime) blocks docs-like HTTP paths (`/docs`, `/_docs`, subpaths, and several bare `/*.md` names) with **404** and `X-Robots-Tag: noindex, nofollow, noarchive`. Internal specs remain in repo `docs/*.md` (Git only, not `public/` or `app/docs`). `scripts/verify-routes.sh` re-checks key URLs after production **`bun run start`** (`bunx --bun next start`) so this cannot silently break. **Unmatched routes** use **`experimental.globalNotFound`** plus `app/global-not-found.tsx` (same UI as `app/not-found.tsx`) so crawlers and the verify script get a real **404** status instead of a streamed **200** with not-found UI.
- **Email:** Resend client in `lib/resend.ts`; templates in `lib/email-templates`. Requires `RESEND_API_KEY` in env. Contact uses fixed `CONTACT_FORM_TO_EMAIL` (`will@lupfr.com`); newsletter internal copy uses `RESEND_TO_EMAIL` (optional env override).

**Invariants.**

- Content is edited via YAML + images only; component code stays stable for content updates.
- API routes enforce explicit validation and in-memory rate limiting before processing requests.
- Contact/newsletter API routes depend on Resend; missing key returns 500 with explicit error message (no silent fallback).
- No server-side secrets or user data beyond what’s needed for sending email / forwarding phone leads to Google Sheets; no in-app persistence of form payloads.

**Home performance.** `components/home-page.tsx` keeps the first viewport immediate (`Navigation`, `Hero`, `Reviews`) and defers the event carousel plus lower sections (`Events`, `Services`, `Artists`, `Gallery`, `About`, `Contact` + `Footer`) behind intersection-observed anchor placeholders. Mobile uses a much smaller lazy-load margin than desktop so phones do not fetch carousel chunks, event images, or lower-section bundles several screens early. The placeholders preserve hash navigation targets before the dynamic chunks mount; matching `location.hash` mounts the requested section immediately. Artist music embeds render as local buttons first and only create Spotify/SoundCloud iframes after an explicit visitor tap, reducing mobile third-party transfer. The mobile hero path is poster/static-copy first and avoids importing Framer Motion; event detail prefetching and first-card image priority stay desktop-only. Scroll stability is part of the home contract: the body gradient uses normal scrolling instead of `background-attachment: fixed`, the fixed navigation veil avoids `backdrop-filter`, section reveals are one-time in-view transforms instead of continuous scroll observers, and metallic heading shine is static by default.

**Hero media performance.** `components/hero-desktop.tsx` keeps optimized real-event WebP posters mounted for the active resolved theme and plays the optimized real ERIA Marina event loop from `public/hero/hero_event_eria_marina.mp4` on desktop. If the active video cannot become playable quickly, the poster remains as the fallback. `next.config.mjs` applies immutable cache headers to `/hero/*` media so repeat visits do not revalidate hero assets.
