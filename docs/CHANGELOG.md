### Fixed

- **Mobile hero photo flashed black between slides (owner report, 2026-08-29, "the images on hero go black for a second when flipping between each one"):** `components/hero-mobile-static.tsx`'s single `<Image>` remounted on every slide change (`key={activePhoto.src}`) and `selectSlide` reset its `ready` flag to `false` — so every manual/auto swap restarted a 500ms opacity-0→100 fade against the section's solid black background, a genuine black dip rather than a loading state, since these six photos are small and load fast. The `<Image>` no longer remounts on slide change (its `src` updates in place, so the browser holds the outgoing frame until the new one decodes) and `ready` is only reset for the very first load. See `docs/DESIGN.md` phase 43. New coverage: `tests/unit/hero-filmstrip-performance.test.ts`, `tests/components/hero-filmstrip-controls.behavior.test.tsx`.
- **Hero manual scroll arrows (and the mobile dots) were dead clicks (owner report, 2026-08-29, "The arrows between slides on hero do not work"):** in both `components/hero-desktop.tsx` and `components/hero-mobile-static.tsx` the bottom copy block is an `absolute inset-0` wrapper — `justify-end` only visually pins its real content to the bottom, but the wrapper's own hit box still covers the *entire* hero, and with no `pointer-events-none` it sat on top of (by explicit/tied z-index and DOM order) the filmstrip slats, the new `HeroFilmstripArrows` buttons, and on mobile the photo dots, silently swallowing every click meant for them — the same class of bug `HeroCornerReadout`'s own `pointer-events-none` already guarded against. Added `pointer-events-none` to both copy-block wrappers and `pointer-events-auto` to their real-content child so the actual buttons/links keep working while empty space passes clicks through. New regression coverage: `tests/unit/hero-filmstrip-performance.test.ts` and `tests/components/hero-filmstrip-controls.behavior.test.tsx`.
- **Brands corp-tree text now centers (owner report, 2026-08-29, "center all text on the corp tree texts"):** `components/brand-tree.tsx`'s two group labels ("Live / Events," "Corporate · Media / Programming") and every brand node's name/status text were left-aligned; both now center. `tests/components/brand-tree.behavior.test.tsx` covers it.
- **Black screen / delay scrolling from About into Team (owner report, 2026-08-29, "there is a delay and black screen"):** both sections are `next/dynamic(..., { ssr: false })` imports mounted by `DeferredHomeSection`, and neither had a `loading` fallback — Next renders nothing for a dynamic import with no `loading` option until its JS chunk resolves, so the instant `DeferredHomeSection` swapped its estimated-height placeholder for the real component, the section's height collapsed to zero for however long that fetch took, the page reflowed under the scroll position, and the viewport showed raw body background until the chunk painted in. `components/home-page.tsx` now hoists both sections' heights into shared `ABOUT_MIN_HEIGHT`/`TEAM_MIN_HEIGHT` constants and passes a `loading` option to each `dynamic()` call rendering a same-sized `aria-hidden` placeholder, so the section never collapses to zero height during the fetch — it swaps one same-sized placeholder for another, then for the real content. See `docs/DESIGN.md` phase 45. New coverage: `tests/unit/look-and-feel.test.ts`.
- **Partiful-sourced event descriptions rendered raw HTML entities (2026-08-29):** the event detail page's `og:description`/`og:title`/`og:image` are scraped from Partiful's HTML via a plain regex (`lib/partiful.ts`'s `parseOgTag`), not an HTML parser — so an apostrophe or ampersand in Partiful's copy, escaped in the source as `&#x27;` / `&amp;` per normal HTML attribute rules, was coming through as that literal escaped text (e.g. "Zusebi&#x27;s SF tour") instead of the decoded character, because React then escapes it a second time when rendering as text. Added a small entity decoder (numeric decimal/hex refs plus the common named ones) applied to every scraped og: value. Covered by new cases in `tests/unit/partiful.test.ts`.
- **SF Post carousel slide now uses a genuine HQ source (2026-08-29):** the first image the owner sent as an "HQ" replacement for the About carousel's press slide (`public/press/sf-post-lupfr-feature.webp`) turned out to be pixel-identical to the existing 1200×600 asset — re-saved at the same size, not actually higher resolution. The owner then supplied the real original (6005×4504 JPEG, full uncropped frame), re-encoded to `2560×1920` via the standard raster pipeline. `components/about.tsx`'s `PRESS_IMAGE_WIDTH`/`PRESS_IMAGE_HEIGHT` updated to match the new source's real dimensions; the carousel's `aspect-[4/5]` + `object-cover` frame already keeps this slide's crop uniform with the other 5 story-graphic slides, so no layout change was needed — the earlier hardcoded 1200×600 hint was just stale intrinsic-size metadata for `next/image`, not the actual on-screen sizing mechanism.
