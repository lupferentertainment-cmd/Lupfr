# Testing

**Stack (authoritative).** **Next.js** (App Router) with **Bun** as the package manager and script runner. **Vitest** is the test runner used with this repo (it is not NestJS; NestJS is not part of the stack). **Vitest** is a separate project from the Vite dev server; tests are `bun run test` / `bun run coverage`, not “Vite UI tests.” For **React component** checks, use **React Testing Library** (queries and user events from the visitor’s perspective). **Branch coverage** is enforced globally alongside statements/lines/functions.

**Current state.** The canonical full gate is **`bun run test`**. It runs the public raster check, a smoke-first Vitest subset, lint + full Vitest coverage thresholds, strict typecheck, production build, client-bundle scan, route smoke, external-link QA, and browser console/runtime crawl. Local developers, pre-commit, GitHub Actions, and `bun run ship:dev` all use this same Bun-owned suite before staging so there is one source of truth.

**Vitest, React 19, and `NODE_ENV`.** In React 19, the CJS production `react` build omits `exports.act`; `react-dom` test utils still call `React.act`, so @testing-library/react fails with *React.act is not a function* if tests run under **`NODE_ENV=production`** (e.g. Vercel’s `bun run test` step). The first **setup** file, `tests/setup/node-env-react.ts`, sets `NODE_ENV` to `test` when it was `production`, before any React import. Order is fixed in `vitest.config.ts` (`setupFiles`). The RTL setup also replaces malformed Bun/Vitest `localStorage` globals with a test-local `Storage` implementation when required, so cookie/contact preference tests are not dependent on shell-local `--localstorage-file` state.

**Coverage policy.** Coverage thresholds are enforced in `vitest.config.ts`:

- Statements: `>= 80%`
- Functions: `>= 80%`
- Lines: `>= 80%`
- Branches: `>= 80%`

**Performance policy.** `scripts/ci.sh` exports **`VITEST_MAX_WORKERS=50%`** by default, and `vitest.config.ts` honors that environment variable with file parallelism enabled. The first Vitest pass is **`bun run _test:smoke`**, a tiny fail-fast subset covering suite wiring, site route constants, external link shape, and content/data integrity; CI mode then runs lint and the full coverage pass before the production build. Operators may tune worker pressure locally with `VITEST_MAX_WORKERS=75% bun run test` on larger machines or skip only the browser crawl with `LUPFR_SKIP_BROWSER_CHECK=1 bun run test`.

**How to write tests.** Prefer **observable behavior**: components — roles, labels, and user events (RTL); HTTP handlers — status codes and JSON shape (integration), not internal call order. Pure helpers (e.g. gallery URL math) may stay as small unit tests when they encode a documented contract.

**Behavioral gaps (gallery).** Core UX that used to be easy to miss in tests: (1) every home **carousel** slide must navigate to **`/gallery/p/[id]?from=home`** (shareable photo page, not `/gallery` alone); (2) **back** from that page (link, Escape, or browser Back after the carousel’s history rewrite) must land on **`/#gallery`**, not **`/gallery`**. **`tests/behavior/gallery-home-journey.test.ts`** asserts the URL contract for every **`GALLERY_CAROUSEL_PHOTOS`** row plus **`homeHistoryReplaceForGalleryBack`**. Helpers stay covered in **`tests/unit/gallery-nav.test.ts`** and **`tests/unit/escape-back.test.ts`**. The carousel applies **`homeHistoryReplaceForGalleryBack`** on primary-click so the history stack’s prior entry is **`/#gallery`** when the user started from **`/`** without that hash.

**Commands.**

- `bun run dev` – one local development server.
- `bun run start` – one local production server command; builds first, then starts the built Next server.
- `bun run _verify:assets` – run the TypeScript asset-crawl integration test directly against the built server. Requires a prior `bun run _build`.
- `bun run test` – **canonical full test suite** used before staging shipment, before production promotion, by the pre-commit hook, and by GitHub Actions. Runs public raster check + smoke-first Vitest subset + lint + full coverage with configurable Vitest workers + build/typecheck + client-bundle scan + route smoke + external-link QA + TypeScript asset-crawl (all routes + page assets for 404s) + headless-browser console/runtime crawl.
- `bun run smoke` – faster local smoke gate: public raster check + smoke-first Vitest subset + lint + build/typecheck + client-bundle scan + route smoke + external-link QA, without coverage or browser-console crawl.
- `bun run ship:dev` – one staging Preview ship command; runs the full gate, then pushes the current clean Git commit to `origin/dev`.
- `bun run promote:prod` – one production promotion command; requires local HEAD == `origin/dev`, re-runs the canonical full gate (`bun run test`) against that exact commit, then fast-forwards `origin/main` from validated `origin/dev` after typed confirmation. Both deploy environments (staging Preview via `ship:dev`, production via `promote:prod`) run the same full gate before any push.
- Internal `_...` scripts in `package.json` are plumbing for these public commands, not operator workflows.
- Next static generation is constrained with `experimental.cpus: 1` so build worker processes do not race `.next` cleanup before internal bundle and route checks inspect the production output.
- Internal bundle verification scans built `.next/static/chunks/**/*.js` for the exact retired hero shine references that caused a production client crash (`shinePositionDelayed` or bare `shinePosition` shorthand). It runs inside `bun run test` and `bun run smoke` after the production build.
- Internal route verification asserts public crawl/discovery endpoints respond (`/robots.txt`, `/sitemap.xml`, `/site.webmanifest`, `/llms.txt`, `/opengraph-image`, `/twitter-image`, favicon root/folder fallbacks, and the legacy `/layout.css` no-op stylesheet), and still enforces **404** for internal-doc URLs (`/docs`, `/docs/overview`, `/README.md`, `/api.md`) so they never become accidental public routes (see `proxy.ts`). Unknown paths must return **404** through the self-contained routed `app/not-found.tsx` fallback; `experimental.globalNotFound` stays disabled because production `next start` can miss the `/_not-found` client-reference manifest.
- **Dynamic link QA (internal + external).** Route verification crawls every internal route reachable from `/` (each must return **200**) via `scripts/extract-internal-routes.mjs`, and additionally health-checks discovered external `<a href>` destinations (Instagram, TikTok, YouTube, Partiful, the Google Calendar “book a call” CTA, etc.) via `scripts/extract-external-links.mjs`. Repeated social share endpoints are collapsed to one live health check per endpoint (`twitter.com/intent/tweet`, Facebook sharer, LinkedIn share-offsite) after every internal route has still been crawled, so gallery share links stay covered without turning the single gate into hundreds of duplicate network calls. External links are fetched with a browser User-Agent and a tolerant policy: a host that answers — even with a bot-block `401/403/405/429` — counts as **alive**; only a **DNS/connection failure**, **404/410**, or **5xx** fails the run, and a timeout is a non-fatal `WARN`. This runs in `bun run test`, `bun run smoke`, GitHub Actions, and `bun run ship:dev` before the `dev` push. Set `VERIFY_ROUTES_SKIP_EXTERNAL=1` to skip just the outbound checks for offline local runs. The static `LINKS` shape contract stays in `tests/unit/links.test.ts`, and the external-link extractor is unit-tested in `tests/unit/extract-external-links.test.ts`.
- **Same clone as `next dev`:** `bun run test`, `bun run smoke`, and `bun run start` use isolated production output when verifying so they do not delete `.next/dev`, then fail fast before the production build if `next dev` is active for this repo. Stop dev before full verification because Next can hang when dev and build run together even with separate output dirs.
- The headless-browser error gate starts the built server, crawls internal routes from `/` in **Chromium** (Playwright), fulfills image/media/font requests with empty `204` responses, skips per-photo `/gallery/p/*` routes to keep large gallery crawls from exhausting `next start`, and **fails on any `console.error`, uncaught page/runtime error (incl. React hydration #418/#423), or same-origin HTTP `>= 400`**. This catches Next.js client/hydration errors that the `curl`-based route checks cannot observe while the route verifier remains responsible for every gallery photo URL and HTTP asset/route status. Expected Next `_rsc` prefetch cancellations (`net::ERR_ABORTED`) and Playwright target-close races during the settle window are logged/ignored instead of failing the gate. It runs inside `bun run test`; port via `VERIFY_CONSOLE_PORT`.

**Vercel enforcement.** `vercel.json` uses `buildCommand: "bun run _build"` so Vercel Preview and Production deployments perform the production Next.js build only. The canonical full gate still runs before staging via `bun run ship:dev`, before commits via pre-commit, and in GitHub Actions with Playwright Chromium installed for browser/runtime crawl support.

**Docs.** Any change to test scope, thresholds, or CI commands must be reflected in this file.

**Navigation visual guardrail.** `tests/unit/navigation-veil.test.ts` asserts that `components/navigation.tsx` uses the `.lupfr-site-header` stateful gradient veil and that `app/globals.css` keeps the masked gradient surface without `backdrop-filter` blur. This protects the fixed nav from regressing to a flat transparent-or-solid strip while avoiding scroll-time blur repaint flicker.

**Home performance guardrail.** `tests/unit/home-performance.test.ts` asserts that the home page mounts `Events` and `Services` eagerly for instant `#events` navigation and a gap-free scroll boundary into Services, keeps later sections behind intersection-observed hash placeholders, only realigns a deferred section when the current hash still targets that section, uses a tight mobile observer margin so lower chunks do not load several screens early, keeps mobile placeholders compact, keeps immediately visible Reviews as a normal import to avoid unused dynamic chunk preload warnings, keeps the base schedule-call CTA free of Framer Motion, and lazy-loads Spotify/SoundCloud iframes without extra opt-in buttons. This protects perceived responsiveness while preserving mobile transfer discipline.

**Dynamic component guardrail.** `tests/unit/dynamic-component.test.ts` asserts that named dynamic component exports resolve to React components and that missing exports throw a source-specific error before React lazy receives `undefined`. `tests/unit/home-performance.test.ts` also blocks unchecked `.then((m) => m.Component)` homepage loaders so deferred sections stay behind the resolver.

**Global fallback guardrail.** `tests/unit/global-fallbacks.test.ts` asserts that document-level global fallbacks stay self-contained and do not import `next/link` or re-export the routed not-found UI. This protects unmatched/error routes from pulling App Router client internals into special global bundles.

**Next config guardrail.** `tests/unit/next-config.test.ts` asserts that the fallback pages-manifest plugin receives Next’s `dev` flag and only runs for production server builds. This protects `next dev` from duplicate `pages-manifest.json` Webpack asset conflicts while preserving production `next start` compatibility checks.

**Hero media performance guardrail.** `tests/unit/hero-video-performance.test.ts` asserts that the desktop hero uses the optimized real ERIA Marina event video with a poster fallback, keeps immutable cache headers on `/hero/*` media, and binds the static shine position before passing it to the title. `tests/unit/globals-gold-theme.test.ts` also keeps the large `LUPFR` wordmark on a static metallic gradient instead of an animated clipped-text shine, avoiding paint jitter over video. `scripts/verify-client-bundle.mjs` adds the deploy-time compiled-bundle check so a stale bare `shinePosition` client reference fails CI before production.

**Data layer performance guardrail.** `tests/performance/data-layer-budgets.test.ts` uses warmup plus small best-of timing samples for ratio checks so CI timer jitter does not hide real regressions or create false failures without making the coverage run spend excessive time inside benchmark loops.

**Light gold visual guardrail.** `tests/unit/globals-gold-theme.test.ts` now treats the accepted light mode as a canonical visual contract: pure-white surfaces, pure-black foregrounds, neutral faint-gray muted fills, transparent borders, the bronzed luxe gold OKLCH values, button gold values, Entertainment line stops, and the full `--gradient-heading-gold` contrast/specular recipe. This protects the approved clean-white / black-ink / bronzed-gold look from drifting back toward cream, visible borders, or bright/glary gold while keeping the dark-mode white-gold lock intact.
