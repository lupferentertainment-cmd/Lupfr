# Testing

**Stack (authoritative).** **Next.js** (App Router) with **Bun** as the package manager and script runner. **Vitest** is the test runner used with this repo (it is not NestJS; NestJS is not part of the stack). **Vitest** is a separate project from the Vite dev server; tests are `bun run test` / `bun run coverage`, not “Vite UI tests.” For **React component** checks, use **React Testing Library** (queries and user events from the visitor’s perspective). **Branch coverage** is enforced globally alongside statements/lines/functions.

**Current state.** The canonical full gate is **`bun run test`**. It runs the public raster check (`scripts/optimize-public-raster.mjs check`: no leftover PNG/JPEG under `public/`, and event/artist card WebPs ≤1600px wide and ≤450KB), a smoke-first Vitest subset, lint + full Vitest coverage thresholds, strict typecheck, production build, client-bundle scan, First Load JS bundle-budget check, route smoke, external-link QA, browser console/runtime crawl (incl. Will homepage Playwright edge gate), and mobile runtime performance check. Local developers, pre-commit, GitHub Actions, `bun run ship:dev`, and **Vercel Preview/Production builds** all use this same Bun-owned suite — one source of truth. **Vercel `buildCommand`** is `LUPFR_SKIP_BROWSER_CHECK=1 bun run test && bun run _build` (`installCommand`: `bun install`). Vitest + route/asset checks still gate the deploy; Playwright is skipped because Vercel cannot install Chromium OS libs (`libnspr4.so`). Local/GHA keep the full browser suite. Operators may still set `LUPFR_SKIP_BROWSER_CHECK=1`, `LUPFR_SKIP_ROUTE_CHECK=1`, or `LUPFR_SKIP_ASSET_CRAWL=1` for offline local runs. **`scripts/verify-routes.sh`** must not use bash process substitution (`/dev/fd`) — Vercel’s sandbox lacks it; link extraction writes to temp files under the script’s mktemp dir.

**Vitest, React 19, and `NODE_ENV`.** In React 19, the CJS production `react` build omits `exports.act`; `react-dom` test utils still call `React.act`, so @testing-library/react fails with *React.act is not a function* if tests run under **`NODE_ENV=production`** (e.g. Vercel’s `bun run test` step). The first **setup** file, `tests/setup/node-env-react.ts`, sets `NODE_ENV` to `test` when it was `production`, before any React import. Order is fixed in `vitest.config.ts` (`setupFiles`). The RTL setup also replaces malformed Bun/Vitest `localStorage` globals with a test-local `Storage` implementation when required, so cookie/contact preference tests are not dependent on shell-local `--localstorage-file` state.

**Coverage policy.** Coverage thresholds are enforced in `vitest.config.ts`:

- Statements: `>= 90%`
- Functions: `>= 90%`
- Lines: `>= 90%`
- Branches: `>= 90%`

The retired SEA//SIDE landing (`components/seaside/**`) and generated JSON under `lib/data/generated/**` are excluded from the coverage denominator. Live LUPFR surfaces stay on the 90% bar.

**Performance policy.** `scripts/ci.sh` exports **`VITEST_MAX_WORKERS=50%`** by default, and `vitest.config.ts` honors that environment variable with file parallelism enabled. The first Vitest pass is **`bun run _test:smoke`**, a tiny fail-fast subset covering suite wiring, site route constants, external link shape, and content/data integrity; CI mode then runs lint and the full coverage pass before the production build. Operators may tune worker pressure locally with `VITEST_MAX_WORKERS=75% bun run test` on larger machines or skip only the browser crawl with `LUPFR_SKIP_BROWSER_CHECK=1 bun run test`. **Test timeouts (`vitest.config.ts`: `testTimeout`/`hookTimeout` = 20000ms, raised from Vitest's 5000ms default, 2026-07-16):** Vercel's Preview build machine (2 cores/8GB, shared/variable load) can run dramatically slower than local dev hardware — one build showed 150s+ of cumulative Vitest transform/setup time vs <1s locally — which flaked two unrelated tests on consecutive builds under the old 5000ms default (`tests/performance/data-layer-budgets.test.ts`'s single-sample `groupGalleryByDateISO` case, fixed separately by switching to best-of-2 sampling; then `tests/integration/newsletter-route.test.ts`'s first test, which does a cold dynamic `import()` of the route module). Both were genuine machine-contention flakes, not code bugs — the global timeout bump is the systemic fix so new tests don't need to opt in individually. **(2026-07-20)** The last single-sample holdout in `data-layer-budgets.test.ts` — the `gallery preload indices at large synthetic length` case — flaked the same way (184ms > its 170ms ceiling on a loaded build machine) and blocked a production deploy; it was converted to the same best-of-2 `bestBulkElapsedMs` sampling as its siblings with a ceiling raised to 300ms. All wall-clock budget cases in that file now sample best-of-2, so a transient load spike no longer fails the gate while a real O(n) regression (orders of magnitude over the ceiling) still would.

**How to write tests.** Prefer **observable behavior**: components — roles, labels, and user events (RTL); HTTP handlers — status codes and JSON shape (integration), not internal call order. Pure helpers (e.g. gallery URL math) may stay as small unit tests when they encode a documented contract.

**Behavioral gaps (gallery).** The home gallery carousel is retired; photos are reached from **event detail pages**. Core URL contract: (1) every event-page photo links to **`/gallery/p/[id]?from=gallery`** (shareable photo page); (2) **back**/Escape from that page lands on **`/gallery`**. **`tests/behavior/gallery-home-journey.test.ts`** asserts that contract for every photo reachable from an event (`getGalleryPhotosByDateISO` across `EVENTS`). Helpers stay covered in **`tests/unit/gallery-nav.test.ts`** and **`tests/unit/escape-back.test.ts`** (the `from=home` / history-rewrite helpers remain in `lib/gallery-nav.ts` for back-compat and stay unit-covered there).

**Commands.**

- `bun run dev` – one local development server.
- `bun run start` – one local production server command; builds first, then starts the built Next server.
- `bun run _verify:assets` – run the TypeScript asset-crawl integration test directly against the built server. Requires a prior `bun run _build`.
- `bun run test` – **canonical full test suite** used before staging shipment, before production promotion, by the pre-commit hook, and by GitHub Actions. Runs public raster check + smoke-first Vitest subset + lint + full coverage with configurable Vitest workers + build/typecheck + client-bundle scan + First Load JS bundle-budget (`_verify:bundle-budget`) + route smoke + external-link QA + TypeScript asset-crawl (all routes + page assets for 404s) + headless-browser console/runtime crawl + mobile runtime performance (`_verify:mobile-perf`). Vitest coverage excludes thin `app/admin/**` and `components/admin/**` shells (auth/API covered separately); see `vitest.config.ts`.
- `bun run smoke` – faster local smoke gate: public raster check + smoke-first Vitest subset + lint + build/typecheck + client-bundle scan + First Load JS bundle-budget + route smoke + external-link QA, without coverage or browser-console / mobile-perf crawl.
- `bun run ship:dev` – one staging Preview ship command; runs the full gate, then pushes the current clean Git commit to `origin/dev`.
- `bun run promote:prod` – one production promotion command; requires local HEAD == `origin/dev`, re-runs the canonical full gate (`bun run test`) against that exact commit, then fast-forwards `origin/main` from validated `origin/dev` after typed confirmation. Both deploy environments (staging Preview via `ship:dev`, production via `promote:prod`) run the same full gate before any push.
- Internal `_...` scripts in `package.json` are plumbing for these public commands, not operator workflows.
- Next static generation is constrained with `experimental.cpus: 1` so build worker processes do not race `.next` cleanup before internal bundle and route checks inspect the production output.
- Internal bundle verification scans built `.next/static/chunks/**/*.js` for the exact retired hero shine references that caused a production client crash (`shinePositionDelayed` or bare `shinePosition` shorthand). It runs inside `bun run test` and `bun run smoke` after the production build.
- Internal route verification asserts public crawl/discovery endpoints respond (`/robots.txt`, `/sitemap.xml`, `/site.webmanifest`, `/llms.txt`, `/opengraph-image`, `/twitter-image`, favicon root/folder fallbacks, and the legacy `/layout.css` no-op stylesheet), enforces **404** for temporary-disabled blog URLs (`/blog`, `/blog/disabled-route-check`), and still enforces **404** for internal-doc URLs (`/docs`, `/docs/overview`, `/README.md`, `/api.md`) so they never become accidental public routes (see `proxy.ts`). Unknown paths must return **404** through the self-contained routed `app/not-found.tsx` fallback; `experimental.globalNotFound` stays disabled because production `next start` can miss the `/_not-found` client-reference manifest.
- **Dynamic link QA (internal + external).** Route verification crawls every internal route reachable from `/` (each must return **200**) via `scripts/extract-internal-routes.mjs`, and additionally health-checks discovered external `<a href>` destinations (Instagram, TikTok, YouTube, Partiful, the Google Calendar “book a call” CTA, etc.) via `scripts/extract-external-links.mjs`. Repeated social share endpoints are collapsed to one live health check per endpoint (`twitter.com/intent/tweet`, Facebook sharer, LinkedIn share-offsite) after every internal route has still been crawled, so gallery share links stay covered without turning the single gate into hundreds of duplicate network calls. External links are fetched with a browser User-Agent and a tolerant policy: a host that answers — even with a bot-block `401/403/405/429` — counts as **alive**; only a **DNS/connection failure**, **404/410**, or **5xx** fails the run, and a timeout is a non-fatal `WARN`. This runs in `bun run test`, `bun run smoke`, GitHub Actions, and `bun run ship:dev` before the `dev` push. Set `VERIFY_ROUTES_SKIP_EXTERNAL=1` to skip just the outbound checks for offline local runs. The static `LINKS` shape contract stays in `tests/unit/links.test.ts`, and the external-link extractor is unit-tested in `tests/unit/extract-external-links.test.ts`.
- **Same clone as `next dev`:** `bun run test`, `bun run smoke`, and `bun run start` use isolated production output when verifying so they do not delete `.next/dev`, then fail fast before the production build if `next dev` is active for this repo. Stop dev before full verification because Next can hang when dev and build run together even with separate output dirs.
- The headless-browser error gate starts the built server, crawls internal routes from `/` in **Chromium** (Playwright), fulfills image/media/font requests with empty `204` responses, skips per-photo `/gallery/p/*` routes to keep large gallery crawls from exhausting `next start`, and **fails on any `console.error`, uncaught page/runtime error (incl. React hydration #418/#423), or same-origin HTTP `>= 400`**.
